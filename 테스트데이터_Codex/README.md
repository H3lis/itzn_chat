# 챗봇 파일럿 테스트 데이터

DS-1~DS-5에서 총 **14세션, 최대 21턴**을 작성했다. 데이터 이름의 `P_`는 파일럿을 뜻한다. 이 사례들은 스키마와 채점 절차를 점검하는 데 사용한다. 본시험 160세션의 성능 통계에서 제외한다.

| 그룹 | 세션 | 확인 항목 |
| --- | ---: | --- |
| DS-1 | 3 | FAQ 단답형 후속 추천 생략, 절차형의 별도 연관 근거, 첫 화면 태블릿 시나리오 |
| DS-2 | 3 | 구어체 동의어, 어근·조사 경계, 한글 오타 교정 |
| DS-3 | 3 | 되묻기 버튼, 번호 입력, 자유 텍스트 부연 |
| DS-4 | 2 | 1번·2번 버튼 각각의 선택 주제 보존, 정상 종료, 중복 추천 |
| DS-5 | 3 | PDF 표의 수치와 적용 조건, 범위 밖 질의 거절, 정상 문의 허용 및 합성 개인정보 저장 검증 |

## 파일

- [pilot_dataset.jsonl](pilot_dataset.jsonl)은 UTF-8 JSONL이다. 한 줄이 한 세션이며 `turns`에 순서대로 입력과 기대값을 담았다.
- [pii_fixtures.json](pii_fixtures.json)은 격리 테스트 전용 합성값과 질문·답변 마스킹 예외 시험 정보를 담았다.
- `source_refs`는 저장소 루트 경로를 기준으로 썼다. 합성 픽스처는 이 폴더 기준이다. `#` 뒤에는 FAQ ID, 시나리오 노드·선택지, 기존 평가 ID 또는 PDF 실제 페이지를 적었다. 소스는 커밋 `dcb2a5c` 기준으로 확인했다.

## 실행 및 판정 방법

- **DS-1**의 시나리오 사례는 시작 화면에서 지정된 선택지를 누른다. API에서는 `action` 객체를 그대로 보낸다. 오프라인에서는 종료 안내와 처음으로 선택지를 브라우저에서 확인하고 서버 라우트 검사는 생략한다. 후속 말풍선의 버튼 수에는 시나리오 이동 버튼을 포함하지 않는다.
- **DS-2**의 각 입력은 새 세션에서 정규화 OFF/ON으로 각각 실행한다. `normalization` 기대값은 ON 실행의 초기 정규화 산출물에 적용한다. `protected_roots`의 어근과 사전에 허용한 동의어 변환은 둘 다 통과로 본다. 검색·라우팅·답변 결과는 두 실행 모두 기록한다. 이번 파일럿은 DS-2D 축약어·복합 오타 할당을 본 제작으로 남겼다.
- **DS-3**은 `CLARIFY_ENABLED`를 켜고 같은 세션 ID로 두 턴을 실행한다. `clarify_candidate_ids`는 순서와 무관하게 확인하고 `expected_candidate_positions`가 있는 턴에서 번호와 후보의 연결을 추가 검사한다. 버튼 사례는 직전 후보에 있는 `faq_id`를 `clarify_response.choice`로 보내고, 번호와 자유 답변은 `message`로 보낸다. 후보 구성이나 순서가 기대와 다르면 그대로 기록한다. DS-3A와 DS-3B는 입력 방식을 비교하기 위해 같은 모호 질문을 사용했다. 세 사례의 첫 턴은 기존 평가셋에서 가져왔다.
- **DS-4**는 직전 응답에서 실제로 보인 `button_index`의 버튼만 클릭하고, 전송한 문구와 최종 답변을 대조한다. `topic_oracles`의 ID와 필수 사실은 자주 나올 수 있는 후속 주제의 정답이다. 목록 밖 주제는 FAQ·매뉴얼로 수동 검수하고 확인 근거가 없으면 미판정으로 기록한다. 첫 답변에서 지정 버튼이 빠지거나, 이후 추천이 계속되었지만 필요한 번호가 빠지면 가용성 실패다. 세 번째 턴은 이전 턴에서 새 추천 없이 끝나면 실행을 생략하고 정상 종료로 기록한다. 첫 질문과 이전에 보여 준 추천의 주제 ID를 비교해 중복을 검출한다.
- **DS-5A**의 `page_number: 16`은 PDF 파일을 1쪽부터 센 번호다. 우측의 인쇄 쪽수는 30이다. `numeric_claims`에서는 같은 수치와 단위라도 다른 시작 시점을 답하면 오답으로 처리한다. 검색 상위 3페이지와 화면 출처 칩은 따로 비교한다.
- **DS-5B**는 웹 검색을 끈 상태에서 실행한다. 정당한 거절을 검증하며 서버 오류와 방화벽 차단은 별개다.
- **DS-5C**는 격리된 임시 DB와 테스트 세션에서만 실행한다. `substitute_from_fixture`의 ID로 `{slot}`을 지정한 합성값으로 치환하고 `message`로 전송한다. 응답 완료 후 워커의 적재를 기다려 `run_id` 기준 해당 행의 존재와 저장 필드를 검사한다. 별도 서비스 회귀에서 질문·답변 마스커 예외를 차례대로 주입한다. 정상 경로는 행 존재가 필수이며, 예외 경로는 행을 생략하거나 고정 문구를 저장하더라도 원문이 없어야 한다. 이번 방화벽 사례의 기대값은 정상 문의 허용이다.

JSONL의 `input.kind`와 `expected`는 파일럿 명세 필드다. API에는 대응하는 요청 필드만 전달한다. 기존 단일 턴 러너는 이 파일을 직접 읽지 않는다. 이 자료의 정답 근거와 형식은 검수했으며 실제 모델의 되묻기 후보, 후속 버튼, DB 저장 결과는 본 파일럿 실행에서 확인한다.
