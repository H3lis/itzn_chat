# 챗봇 DS-1~DS-5 파일럿 통합 테스트 결과

- 시험일 2026-11-26. 대상 커밋 `7e23942`와 [Codex 파일럿 14세션](pilot_dataset.jsonl)을 사용했다.
- 실제 FastAPI `/api/chat/stream`을 ASGI 테스트 클라이언트로 호출했다. LangGraph 체크포인트, 복제 FAQ·시나리오·색인, 로컬 Ollama `qwen2.5:3b`·`embeddinggemma`, CPU 리랭커 `BAAI/bge-reranker-v2-m3`를 사용했다. 되묻기를 켜고 웹 검색과 응답 TTL 캐시를 껐다. 온라인·오프라인 태블릿 시나리오는 Chrome으로 확인했다.
- 자동 승인 검토가 파일럿 입력과 내부 문서 근거의 외부 전송 가능성을 이유로 Gemini/GCP 모델 실행을 차단했다. 아래 결과의 범위는 로컬 모델 구성이다. 운영 DB와 별도로 복제 데이터 디렉터리·임시 DB를 사용했다.
- 세션이 요구한 필수 조건을 모두 충족하면 성공으로 집계했다. 첫 턴에서 필요한 후보·버튼이 누락된 경우 후속 턴은 미실행으로 표시했다. DS-2의 OFF 비교와 DS-5C 예외 주입 2건은 추가 비교이며 14세션 합계에 포함하지 않았다.

## 전체 판정

**14세션 중 8세션 성공, 6세션 실패.** 예정된 최대 21턴 가운데 1턴은 정상 종료 조건으로 생략했고, 판정에 사용한 실제 채팅 요청은 20턴이다. 중단한 첫 표 질의와 별도 비교 실행은 이 합계에서 제외한다.

| 그룹 | 성공 | 실패 | 주요 결과 |
| --- | ---: | ---: | --- |
| DS-1 | 2 | 1 | 단답형과 태블릿 시나리오 통과. 절차형 요약·추천 중복 실패. |
| DS-2 | 1 | 2 | 구어체·오타 변화 관측. 두 문항이 바로 답하지 않고 되물음. |
| DS-3 | 3 | 0 | 버튼·번호·자유 입력으로 목표 FAQ 도달. |
| DS-4 | 1 | 1 | 두 버튼의 선택 주제 전달 성공. 1번 연속 사례에서 이미 안내한 주제 재추천. |
| DS-5 | 1 | 2 | 범위 밖 질의 거절 성공. 표의 시간 기준점 오류, 상담 보류 및 평문 저장 실패. |

가장 먼저 마스킹 예외에서 원문 적재를 막고 단독 이름 탐지를 보강할 필요가 있다. 그다음 표 답변의 조건 검증과 응답 시간 제한, FAQ 요약·추천 중복을 수정한다.

### DS-2 구어체와 오타

| 세션 | 판정 | 정규화 ON의 관측 |
| --- | --- | --- |
| P_DS2A_001 | 실패 | `랜선`이 `UTP케이블`로 바뀌었다. 목표 `학내망:5`가 1위였지만 점수 차 0.0162로 되묻기를 보냈다. |
| P_DS2B_001 | 성공 | 입력이 정준 FAQ와 정확히 일치해 `학내망:10`으로 답했다. 전처리 우회가 기록되어 이 사례로는 어근 보호 효과를 판정할 수 없다. |
| P_DS2C_001 | 실패 | `인텨넷`이 `인터넷`으로 교정됐다. 목표 `무선망:16`가 1위였지만 점수 차 0.0394로 되묻기를 보냈다. |

OFF에서는 `랜선`과 `인텨넷`이 그대로 남았다. ON에서 두 문항의 1·2위 점수 차가 각각 0.0093 → 0.0162, 0.0302 → 0.0394로 늘었지만, 세 문항 모두 1위 FAQ와 최종 라우트가 OFF와 같았다. 이 세션에서는 표현 교정 효과를 확인했고 직접 답변을 회복한 사례는 0건이었다.

**수정할 부분** — DS-2B 문장을 정준 질문과 일치하지 않는 조사 결합 변형으로 교체한다. DS-2A의 한 PC·옆자리 정상, DS-2C의 AP·비밀번호 정상처럼 장비와 장애 범위를 명시한 단서를 후보 점수에 반영할지 검증한다. 실제로 모호한 DS-3 질문을 함께 실행해 되묻기 회귀를 막는다. [입력 정규화 코드](../chatbot_demo_v2/graph/nodes.py#L468) · [라우팅 분기](../chatbot_demo_v2/graph/routing.py#L68)

### DS-4 후속 질문

| 세션 | 판정 | 관측 |
| --- | --- | --- |
| P_DS4A_001 | 실패 | 1번 버튼을 두 번 선택해 각각 `유무선통합관제:6`과 `유무선통합관제:40`으로 연결됐다. 1턴의 추천은 첫 질문과 겹치는 신규 이용 시작·기관 등록을 다시 제안했다. 첫 요약에 기관 등록 안내도 이미 포함돼 있었다. |
| P_DS4B_001 | 성공 | 첫 답변에서 두 후보가 노출됐다. 2번의 AP 전원 공급 방식으로 `무선망:4`가 선택돼 PoE로 전원과 데이터를 공급한다고 답했다. 1번 Link 점검으로 바뀌지 않았다. 이후 새 추천이 없어 계획한 3턴은 정상 종료했다. |

**수정할 부분** — 후속 질문에 FAQ ID와 주제 ID를 연결하고 현재 답변·기존 질문·이미 노출한 추천을 같은 기준으로 대조한다. 검증 세트는 2번 버튼이 연속 노출되는 사례를 추가해 두 번 이상의 선택도 시험한다. 이번 실측은 2번 클릭 1회와 정상 종료까지다. 로컬에서 이 세션의 첫 답변 완료는 238.61초였다. 프런트엔드의 후속 질문 파서를 실제 API 응답에 적용해 클릭 대상과 전송 문구가 일치하는지도 확인했다.

### DS-5 표·도표, 범위 밖 질의, 개인정보

DS-5A 첫 요청은 약 610초 동안 최종 SSE 응답이 없어 중단했다. DS-5 세션은 같은 모델·색인에서 최대 생성 384토큰과 길이 초과 재시도 비활성 조건으로 실행했다. 첫 실행의 상한은 1,536토큰이고 길이 초과 재시도가 활성화돼 있었다.

| 세션 | 판정 | 관측 |
| --- | --- | --- |
| P_DS5A_001 | 실패 | 재시험에서 정답 PDF 16쪽이 검색 1위였고 API 근거에 포함됐다. 장애 발생 후 30분 이내 통보는 맞았으나, 복구 1시간의 기산점을 정답인 **장애 통보 시점** 대신 **장애 발생 시점**으로 답했다. `confidence: abstain`인데도 단정형 본문이 노출됐다. 재시험도 378.52초로 설정된 180초를 넘었다. |
| P_DS5B_001 | 성공 | `abstain`으로 응답했다. 내부 자료로 확인하기 어렵다고 알렸고 급식 메뉴를 지어내지 않았다. |
| P_DS5C_001 | 실패 | 방화벽은 정상 질의를 허용했으나 상담 답변을 보류했다. 비동기 저장 행은 생성됐고 `raw_question`은 비었다. 전화·IP·MAC·시리얼은 마스킹됐으며 단독 합성 이름 1/5개가 `masked_question`에 평문으로 남았다. |

격리 저장 서비스에서 질문 마스커 예외를 주입하자 5개 값 모두 `masked_question`에 남았다. 답변 마스커 예외에서는 합성 시리얼이 `final_answer`에 남았다. 두 경우 모두 행이 실제로 생성됐다. 답변 예외 시험에서도 정상 질문 마스킹 단계의 단독 이름 잔존을 확인했다.

**수정할 부분**

1. **마스킹 실패 시 원문 적재 차단.** 질문·답변 마스킹 예외나 빈 결과에서는 원문으로 대체하지 않고 저장을 건너뛰거나 고정 문구를 남긴다. 정상 경로에서 단독 인명을 보강하고, 질문·답변 각각의 예외와 저장 재시도를 회귀 검증한다. [이력 저장 코드](../chatbot_demo_v2/app/history_service.py#L122) · [이름 마스킹 코드](../chatbot_demo_v2/app/pii_service.py#L978)
2. **표 근거와 답변 조건 검증.** 표의 행·열과 숫자·단위·기산점을 한 묶음으로 확인한다. 검증에서 보류된 초안을 답변 합성이나 최종 포맷 단계에서 단정형 본문으로 표시하지 않도록 한다. 파일럿에서 확인한 출처는 API의 근거 페이지이며, 브라우저 출처 칩은 추가 검증 대상이다. [수치 검증 코드](../chatbot_demo_v2/ragcore/rag3/verify.py#L61) · [최종 응답 코드](../chatbot_demo_v2/graph/nodes.py#L1536)
3. **응답 시간 제한 적용.** 로컬에서 리랭킹과 추론이 모두 길어질 수 있었다. 단계별 시간과 재시도를 계측하고, 남은 시간 예산을 리랭킹과 모델 요청에 적용해 제한을 넘기면 보류나 제한시간 오류를 반환한다. [RAG 시간 제한 코드](../chatbot_demo_v2/graph/rag_nodes.py#L142)
