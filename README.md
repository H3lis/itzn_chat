# 🏫 학교 유무선 네트워크 장애상담 지능형 챗봇 통합 플랫폼 (`H3lis/itzn_chat`)

> **초·중·고 학내망 장애 발생 시 결코 멈추지 않는 온·오프라인 하이브리드 AI 지원 시스템**  
> 무인터넷 망분리 환경 자립 구동(0초 기동) + LangGraph 기반 하이브리드 RAG + 2단계 개인정보(PII) 비식별화 + 온·오프라인 3-Tier 자동 동기화

## 🌟 프로젝트 개요 (Overview)

본 프로젝트는 전국 초·중·고등학교 및 교육 행정 기관에서 발생하는 유무선 네트워크 장애(인터넷 단절, 무선 AP 고장, IP 주소 충돌, 관제시스템 로그인 장애 등)를 교직원이 스스로 진단하고 신속하게 해결할 수 있도록 지원하는 **지능형 하이브리드 장애상담 챗봇 플랫폼**입니다.

### 💡 핵심 차별점: "인터넷이 끊겨도 멈추지 않는 챗봇"
기존 웹 챗봇은 네트워크가 끊어지면 챗봇 접속 자체가 불가능한 **구조적 딜레마(Chicken-and-Egg Problem)**를 겪었습니다.  
본 시스템은 브라우저 스토리지와 독립 실행 단일 번들러를 유기적으로 결합한 **하이브리드 3-Tier 아키텍처**를 구축하여:
1. **완전 단절 환경(0% 인터넷)**: 바탕화면의 **단 1개 독립 HTML 파일(608KB)**로 즉시 기동하여 8대 장애 시나리오 조치 매뉴얼 및 과거 상담 기록 열람 (지연 시간 0ms).
2. **정상 연결 환경(100% 인터넷)**: Gemini / Qwen sLLM과 결합한 실시간 RAG 스트리밍 질의응답 및 상담 내역 영구 적재.
3. **무중단 자동 동기화**: 인터넷이 재연결되는 즉시 백그라운드에서 최신 시나리오 트리 및 상담 히스토리를 100% 자동 머지.

### 1. 하이브리드 3-Tier 계층형 로딩 체계
- **Tier 1 (최신 캐시 로드)**: 브라우저 `localStorage`에 이전에 자동 동기화된 최신 시나리오 트리 및 온·오프라인 대화 세션 목록을 0ms 우선 로드.
- **Tier 2 (내장 폴백 안전망)**: 캐시가 전혀 없는 신규 PC나 완전 망분리 PC에서는 단일 HTML 내부에 사전 압축 패키징된 `defaultScenarios.json`으로 즉각 기동.
- **Tier 3 (무중단 백그라운드 동기화)**: 온라인 감지 시 `useAutoSync`가 화면 렌더링을 방해하지 않고 `GET /api/scenarios/latest`를 프로빙하여 최신 시나리오를 자동 덮어쓰고, 서버 상담 내역을 로컬로 복원·병합.

### 2. 2단계 하이브리드 개인정보(PII) 비식별화 파이프라인
- **1단계 (고속 결정론적 정규식 필터)**: 주민등록번호, 휴대전화번호, 외국인등록번호, 카드번호, IP/MAC 주소, 교원 사번 등을 0.005초 만에 100% 마스킹.
- **2단계 (문맥 인지형 sLLM 필터)**: 이름, 주소, 비정형 계정 정보 등 정규식으로 탐지가 어려운 복합 정보를 온디바이스/클라우드 sLLM(Gemini / Qwen)이 문맥을 분석하여 정밀 마스킹.
- **보안 보장**: 비식별화된 데이터만 `chat_history.db`에 적재되며, 오프라인 파일과 동기화할 때도 개인정보 누출이 원천 차단됩니다.

## ⚡ 빠른 시작 가이드 (Quick Start)

### 1. 오프라인 단독 실행 (무설치 0초 기동)
네트워크 연결이 전혀 없는 PC에서도 브라우저만 있으면 즉시 실행할 수 있습니다:
1. 저장소 루트의 [`학교챗봇_장애대응가이드_오프라인.html`](학교챗봇_장애대응가이드_오프라인.html) 파일을 더블클릭합니다.
2. 크롬, 엣지, 웨일 등 일반 브라우저에서 0초 만에 화면이 열리며 8대 네트워크 장애 조치 가이드가 즉각 제공됩니다.

### 2. 로컬 풀스택 서버 원클릭 실행 (가장 추천)
1. 저장소 루트의 [`run_chatbot.bat`](run_chatbot.bat)을 더블클릭합니다.
   - 자동으로 로컬 파이썬 가상환경(`.venv`)을 감지하여 백엔드 서버를 구동합니다.
2. 웹 브라우저를 열고 **`http://127.0.0.1:8002/`** 로 접속합니다.
   - 고객 상담 화면: `http://127.0.0.1:8002/`
   - 관리자 콘솔: `http://127.0.0.1:8002/admin`

### 3. 터미널(CLI) 수동 실행
```powershell
# 1) 가상환경 활성화 (PowerShell)
cd "c:\Users\ITZN\Desktop\챗봇"
.\.venv\Scripts\Activate.ps1

# 2) 챗봇 서버 기동
python -m chatbot_demo_v2 --port 8002

# 3) 브라우저 접속: http://localhost:8002/
```

### 4. 프론트엔드 단일 오프라인 배포 파일 빌드 (Standalone)
시나리오 트리나 UI 컴포넌트를 수정한 후 최신 오프라인 단일 실행 파일을 새로 빌드할 때 사용합니다:
```bash

cd chatbot_demo_v2/frontend

# 2) 단일 HTML 번들 빌드 (dist-standalone/index.html 생성)
npm run build:standalone

# 3) 최신 번들을 프로젝트 루트 배포본으로 복사
cp dist-standalone/index.html ../../학교챗봇_장애대응가이드_오프라인.html
```

## 🛠️ 주요 학교 네트워크 장애 대응 시나리오 (8대 카테고리)

오프라인 단일 파일 내부에 탑재되어 0ms 무지연 안내를 제공하는 8대 핵심 시나리오 트리의 구성 내용입니다:

1. **🌐 인터넷이 안 돼요 (`internet_down`)**: 전 구역 불통 vs 일부 교실 불통 ➔ 통신실 메인 스위치 점검 ➔ 헬프데스크(1588-5509) 긴급 인입.
2. **⚡ 인터넷이 느려요 (`internet_slow`)**: 전교생 트래픽 폭주 점검 ➔ 대역폭 QOS 확인 ➔ 교실 무선 AP 재부팅 가이드.
3. **💻 내 PC만 인터넷이 안 돼요 (`my_pc_only`)**: 본체 뒷면 랜선 포트 LED 확인 ➔ 케이블 재체결 ➔ Windows `ipconfig /renew` IP 재할당.
4. **🔋 테블릿의 전원이 안 켜져요 (`tablet_power`)**: 충전 보관함 스위치 확인 ➔ 전원+볼륨다운 버튼 10초 강제 하드 리셋(Hard Reset).
5. **📶 테블릿의 와이파이 연결이 안 돼요 (`tablet_wifi`)**: 교내 전용 보안 SSID 선택 ➔ 네트워크 프로파일 삭제 후 재인증 ➔ 학교 MDM 동기화.
6. **🔑 관제시스템(NMS) 로그인 계정이 없어요/몰라요 (`nms_no_account`)**: 학교 1교 1계정 원칙 안내 ➔ 비번 재발급 및 교육청 통합관제센터 확인.
7. **💡 AP(무선공유기)에 불이 안 들어와요 (`ap_no_light`)**: PoE(Power over Ethernet) 인젝터 전원 플러그 점검 ➔ 스위치 허브 전원 확인.
8. **📞 장애문의 콜센터 전화번호 안내 (`callcenter`)**: 스쿨넷 통합 유지보수 지원센터(☎ **1588-5509**) 및 접수 시 필수 확인 정보 안내.

## 🔧 운영 유지보수 가이드 (Maintenance Guide)

### 서버 IP 또는 포트 변경 시 대처 방법
1. **웹 브라우저 접속 환경 (`http://새주소:포트/`)**:
   - 프론트엔드가 모든 백엔드 호출을 상대 경로(`/api/...`)로 수행하므로 **코드 수정 없이 0초 만에 즉시 호환**됩니다.
2. **로컬 단일 HTML 파일(`file:///`) 환경**:
   - **메모장 치환**: `학교챗봇_장애대응가이드_오프라인.html`을 열고 `Ctrl+H`로 `http://34.64.143.198:8002`를 `http://새서버주소:포트`로 1초 치환.
   - **PowerShell 자동 치환**:
     ```powershell
     (Get-Content -Path "학교챗봇_장애대응가이드_오프라인.html" -Encoding UTF8) -replace 'http://34\.64\.143\.198:8002', 'http://새주소:포트' | Set-Content -Path "학교챗봇_장애대응가이드_오프라인.html" -Encoding UTF8
     ```
   - 백엔드에 `CORSMiddleware(allow_origins=["*"])`가 내장되어 있어 새 주소에서도 CORS 차단 없이 정상 통신됩니다.
