# 챗봇 E2E 파일럿 테스트 데이터 (Claude 작성)

[실험용 데이터셋 생성 및 통합평가 가이드](../챗봇_실험용_데이터셋_생성_및_통합평가_가이드.md) 6장 1단계에 따라 DS-1~DS-5에서 **14세션, 최대 24턴**을 작성했다. 세션 ID의 `CL_`은 이 폴더의 파일럿을 뜻한다. 파일럿 사례는 스키마와 채점 절차 점검용이며 본시험 160세션 통계에는 넣지 않는다. 본시험에서는 이 사례와 같은 정준 질문에서 만든 변형도 제외한다.

## 실행·판정 규칙

- **공통**: 실행마다 커밋, 데이터·색인 버전, 모델, 캐시 상태, `CLARIFY_*`·`ROBUSTNESS_TOOL_ENABLED`·웹 검색 설정을 기록한다. 세션마다 새 `session_id`를 발급하고, 한 세션의 모든 턴에서 그 ID를 유지한다.
- **DS-1**: `followup.presence`가 `absent`이면 두 번째 말풍선이 없어야 한다. `required`이면 추천 영역이 하나이고 버튼이 `max_buttons` 이하여야 한다. `must_not_repeat_body_topics`의 주제를 추천하면 기준 A 위반이다. 시나리오 세션은 `pre_node_id` 상태에서 `action`을 그대로 보내고 `scenario.node_id`, `completed`, 선택지 목록을 비교한다. "처음으로" 버튼은 후속 버튼 수에 넣지 않는다.
- **DS-2**: 같은 입력을 새 세션에서 `ROBUSTNESS_TOOL_ENABLED` OFF/ON으로 한 번씩 실행한다. `normalization`은 ON 실행의 초기 정규화 산출물에만 적용하고, 맥락 재작성 산출물과 구분한다. 검색 Hit@k, 리랭커 점수, 최종 답변은 두 실행 모두 기록한다. `local_dictionary_observation`은 RAG 색인 어휘를 주입하지 않은 로컬 엔진에서 얻은 값이다. 실서버 사전 결과가 다르면 그 결과를 그대로 기록한다.
- **DS-3**: `CLARIFY_ENABLED=true`로 실행한다. `clarify_candidate_ids`는 반드시 포함돼야 하는 후보이며 순서는 보지 않는다. `acceptable_extra_candidate_ids`는 함께 나와도 되는 후보다. 버튼 선택은 1턴 후보에 해당 `faq_id`가 있을 때만 보낸다. 없으면 2턴을 실행하지 않고 "후보 누락"으로 기록한다. DS-3B의 번호 해석은 실제 후보 목록의 2번째 ID와 2턴 답변 FAQ가 일치하는지로 판정한다. 목표 후보(스쿨넷:46)가 2번에 있었는지는 별도로 기록한다. DS-3C에서 2턴이 다시 되묻기면 "연속 되묻기" 실패다.
- **DS-4**: 직전 응답 `.followup-bubble`에 실제로 보인 `button_index` 버튼의 문구만 `message`로 보낸다. 필요한 번호의 버튼이 없으면 **가용성 실패**로 기록하고 다른 버튼을 누르지 않는다. `allow_end: true`인 턴에서 새 추천 없이 끝나면 정상 종료로 기록하고 남은 턴(`skip_if_previous_ended`)은 생략한다. `topic_oracles`는 나올 가능성이 높은 주제의 정답 사실이다. 목록 밖 주제는 FAQ·매뉴얼로 수동 검수한다. DS-4B는 답변이 같은 응답의 1번 버튼 주제로 바뀌지 않았는지도 확인한다.
- **DS-5A**: `page_number`는 PDF를 1부터 센 물리 쪽이다. 해당 쪽에는 인쇄 쪽 번호가 없다. `Page_Hit@3` 검색 순위와 화면 출처·`citations`를 따로 채점한다. 30분 이외의 주기를 단정하면 수치 불일치다.
- **DS-5B**: 웹 검색을 끈 상태로 실행한다. `confidence`, `source_meta`, 사용자에게 보인 답변을 근거로 거절 여부를 판정한다. `security_block`, API 오류, 타임아웃은 거절로 세지 않는다.
- **DS-5C**: 격리된 임시 `chat_history.db`에서만 실행한다. `text_template`에 픽스처 값을 넣어 전송한 뒤 워커 적재를 기다리고 `run_id`로 행을 조회한다. `raw_question`은 빈 문자열이어야 한다. `masked_question`과 `final_answer`에 각 합성값의 전체 문자열이 남으면 잔존이다. 성씨나 전화번호 끝 4자리 같은 부분 노출은 마스킹 정책 결과로 보고 따로 기록한다. 행이 없거나 저장이 타임아웃되면 미측정으로 처리한다. 예외 변형 2종(`CL_PII_001_QEXC`, `CL_PII_001_AEXC`)은 서비스 단위 회귀 시험에서 주입한다. 현행 `history_service.py`는 예외가 나면 원문으로 대체하므로 이 변형은 실패할 것으로 예상하며, 실패하면 그 사실을 기록한다. 리포트에는 합성값 대신 픽스처 ID와 판정만 남긴다.

## 작성 시 검증한 내용

`validate_pilot.py`로 아래를 확인했고 모두 통과했다.

- JSONL 파싱, 필수 키, `turn_index` 연속성, `input.kind` 규격, 그룹별 2~3세션
- 참조한 FAQ ID 전부가 `faq.json`에 있음. 시나리오 3단계 전이, 선택지 목록, 종단 여부가 `scenarios.json`과 일치함
- DS-5A의 PDF SHA-256과 22쪽 표 셀 문자열("AP 접속 단말수 확인", "30분", "실제 접속한 단말 수와 차이가 있을 수 있음"). 22쪽 이미지를 렌더링해 행·열 위치도 확인함
- DS-2 세 입력의 로컬 정규화 결과
  - 게이트웨이 → 보존
  - 와ㅣ파이 비번 → 무선랜 비밀번호
  - 랜썬 연결표 → 선번장
- DS-5C 합성 문장을 1차 규칙 마스커(`skip_sllm=True`)에 통과시킨 결과, 전체 값 잔존 0/5. 검출 유형: name, phone, ipv4, mac, serial

실서버 API·브라우저·오프라인 HTML 실행, 실모델 답변, 되묻기 후보와 순서, 후속 버튼, 격리 DB 적재는 아직 확인하지 않았다. 이 항목들은 본 파일럿을 실행하면서 측정한다.

로컬 정규화에서 발견한 사항이 있다. "랜썬 연결표가"는 "선번장가"로 바뀌어 조사가 맞지 않게 남는다. "와이파이가"처럼 사전 단어에 조사가 붙은 어절에서는 조사가 사라진다(예: "와이파이가 끊겨요" → "무선랜 끊겨요"). 둘 다 검색에 영향을 주는지는 DS-2 ON/OFF 결과로 판단한다.
