# 챗봇 파일럿 통합테스트 결과 및 개선사항

> 실행일 2026-11-26 · 대상 `chatbot_demo_v2` (커밋 `7e23942`) · 데이터 `테스트데이터_Claude`(14세션)·`테스트데이터_Codex`(14세션)·`테스트데이터_Gemini`(16세션), 총 44세션 60턴 실행
>
> 파일럿 결과다. 그룹당 2~5세션이므로 비율은 경향만 보여 준다. 모든 비율에 분자/분모를 함께 적었다.

## 1. 요약

- **잘 되는 부분**: 시나리오 버튼(5/5), 범위 밖 질의 거절(3/3), 방화벽 차단(1/1, 정상 상담 오탐 0/3), FAQ로 답한 턴의 FAQ 정확도(19/20), 되묻기 1턴 발동(9/9), 번호 응답("1번이요/2번이요") 해석(3/3)은 기대대로 동작했다. 수치 답변에서 틀린 숫자를 만든 경우는 0건이다.
- **가장 큰 문제 5가지**
  1. **개인정보 원문 적재**: 마스커 예외를 주입하면 질문 원문이 `masked_question`에 그대로 저장된다(3개 픽스처 모두, 값 5/5). 정상 경로에서도 **줄 하나에 이름만 쓴 경우** 이름이 마스킹되지 않았다(실서버 DB 2/3 세션).
  2. **거의 완전 일치하는 질문에서 되묻기 과발동**: 최고 점수가 0.998~1.000인데도 2위와의 차이(margin)가 0.30보다 작다는 이유로 되묻기를 했다. 답변을 기대한 턴 6건이 이렇게 실패했고, DS-4 세션 3개가 이 때문에 멈췄다.
  3. **정규화 엔진 과교정**: `IP`를 `AP`로 바꾼다(4턴에서 관측). `하는`을 `설치`로 바꾸고, 반복된 단어(`몇` 등)를 지워 질문 뜻을 바꾼다.
  4. **되묻기 후보 품질**: 후보가 항상 2개이고, 관련 없는 저점수 후보(0.077)도 제시된다. 사용자가 그 후보를 고르면 엉뚱한 답이 나온다(2/9 세션).
  5. **2단 레이아웃 표 파싱**: 5단계 가이드 p11·p16에서 옆 단의 표와 섞여 색인되어, 제주 요금(2,907,000원)과 SLA(30분/1시간)를 "명시되어 있지 않다"고 답했다.

## 2. 실행 조건

| 항목 | 값 |
| --- | --- |
| 경로 | 로컬 서버의 온라인 API `/api/chat`(JSON). 운영 DB 오염을 막기 위해 `DEMO_DATA_DIR`를 임시 폴더로 지정해 **격리된 `chat_history.db`·`audit_log.db`** 사용 |
| 모델·검색 | `RAG_BACKEND=gemini`(GEMINI_MODEL=gemini-2.5-pro), 리랭커·Ollama는 GCP L4 엔드포인트(34.64.143.198) |
| 매처·되묻기 | semantic, `SCENARIO_MATCH_THRESHOLD=0.8`, `MARGIN=0.30`, `CLARIFY_ENABLED=true`, `CLARIFY_MIN_SCORE=0.35` |
| 기타 | 웹 검색 OFF, `RAG_CACHE_TTL_S=0`(캐시 없음), composer·contextualize·grader ON, `PII_BACKEND=rule` |
| 정규화 비교 | DS-2 9세션을 `ROBUSTNESS_TOOL_ENABLED` ON(포트 8111)과 OFF(포트 8112)에서 각각 실행했다. 나머지 설정은 같다. |
| 보조 검증 | 오프라인 HTML 내장 시나리오 데이터 대조, `HistoryService` 마스커 예외 주입 회귀, `PromptGuard` 단위 판정 |
| 재실행 | DS-5A 4세션을 다시 실행했고 답변이 같았다. 나머지는 1회 실행이다. |

판정 방식: 라우트, 응답 종류, FAQ ID, 되묻기 후보, 버튼 수, 시나리오 노드, DB 잔존은 자동으로 채점했다([auto_scores.json](raw/auto_scores.json)). 답변 사실, 주제 일치, 수치, 인용은 [대조표](raw/review_sheet.md)를 보고 수동으로 판정했다. 후속 버튼은 프런트엔드 `extractFollowupData()`와 BotMessage의 후보 폴백 규칙을 그대로 옮겨 계산했다.

## 5. 챗봇 개선 과제 (우선순위순)

### P0. 개인정보

1. **마스커 예외 시 원문 대체 제거**: [history_service.py:144-152](../chatbot_demo_v2/app/history_service.py#L144-L152)의 `MaskResult(masked_text=raw_question)` 폴백 때문에 예외가 나면 원문이 `masked_question`·`final_answer`로 저장된다. 고정 문구(`[마스킹 실패로 저장 생략]`) 저장이나 행 생략 중 하나로 정하고, 이를 회귀 테스트로 고정할 것. 근거: [offline_service_checks.json](raw/offline_service_checks.json) `*/question`, `*/answer`.
2. **단독 이름 줄 검출**: 메시지 첫 줄이 이름만인 입력(`P_PII_001`, `GEMINI_PII_001`의 `synthetic_name`)을 규칙 엔진이 놓친다. `CL_PII_001`처럼 "{이름}입니다"로 서술어가 붙으면 검출된다. 줄 단위로 성씨 사전과 2~4음절 고유명사를 판정하는 규칙을 추가할 것.
3. 방화벽 감사로그 `payload_summary.blocked_query`에 차단 원문이 그대로 저장된다. 공격 문장에 개인정보가 섞이면 남으므로 같은 마스커를 적용할 것.

### P1. 라우팅·되묻기

4. **거의 일치하는 질문은 margin 규칙을 면제**: semantic 최고 점수가 0.97 이상이면 2위와의 차이가 작아도 1위를 채택하도록 바꿀 것. 6건 모두 1위 0.998~1.000, 2위 0.81~0.98이었다. 또는 1·2위가 같은 장애 유형이면 1위로 답하고 2위를 후속 추천으로 돌릴 것. 무선망:3과 무선망:50, 무선망:49와 학내망:22처럼 의미가 겹치는 FAQ 쌍은 통합이나 대표 지정을 검토한다.
5. **되묻기 후보 필터와 개수**: `CLARIFY_MIN_SCORE`(0.35)보다 낮은 후보(0.077 등)는 제시하지 말 것. 남은 후보가 1개뿐이면 되묻기 대신 답할 것. "로그인이 안 돼요"처럼 의도가 3개 이상인 질문은 3개까지 보여 줄 것(필수 후보 포함률 3/8).
6. 후속 버튼을 클릭해 보낸 문장(`네, …에 대해 알려주세요`)은 되묻기 대상에서 빼고 바로 답할 것(Codex DS4A).

### P1. 정규화 엔진 (`robustness_tool/core.py`)

7. **영문·숫자 토큰은 오타 교정에서 제외**: `correct_typo('IP') → 'AP'`(자모 거리 1). DS-5C 3세션과 Gemini DS4B에서 질문의 IP가 AP로 바뀌었다. `[A-Za-z0-9]` 토큰과 도메인 약어(IP, AP, PC, MAC, SSID, DNS)는 바이패스할 것.
8. **용언·어미 교정 금지**: `하는 → 까는 → 설치`(Gemini DS3C). 2음절 이하 용언, 어미는 교정 대상에서 뺄 것.
9. **중복 제거가 뜻을 바꿈**: `deduplicate_query`가 "몇 분 … 몇 시간"의 두 번째 `몇`, 반복된 `WiFi`를 지운다. 기능어·의문사는 중복 제거에서 제외할 것.
10. 치환 후 조사를 받침에 맞게 다시 붙일 것(`선번장가`, `무선랜는`).

### P1. 문서 파싱·검색

11. **2단 레이아웃 표 분리 재색인**: 5단계 가이드 p11(DR 요금표와 IPsec VPN 요금표)과 p16(SLA 표 좌우 단)이 한 텍스트로 섞여 있다. 답변 모델이 제주 열과 30분/1시간을 읽지 못했다. 단 단위 crop이나 표 구조(MinerU 표 HTML)를 청크에 쓰고 재색인할 것. 재색인 후 Codex DS5A와 Gemini DS5A_001로 회귀 확인.
12. RAG 답변이 근거를 못 찾으면 `confidence=abstain`이 나오는데, 화면에는 일반 답변처럼 표시된다(Codex DS5A, Claude DS5C). 낮은 신뢰도 답변에 표시를 붙이거나 표현을 구분할 것.

### P2. 답변·후속 추천 품질

13. **FAQ composer 요약 사실 왜곡**: 25건 중 3건이 원문과 모순되거나 의미가 반대다(Gemini DS1A·DS2B·DS4A). 질문을 그대로 반복한 요약도 2건 있다. 요약을 원문 문장에서 추출하도록 제한하거나, grader가 `<summary>`와 원문의 일치도 검사하게 할 것.
14. **후속 버튼 형식**: `|`로 구분된 옵션을 분리할 것. "…보시겠습니까", "…려면" 같은 문장형 꼬리는 버튼에서 거를 것. 서버 `_extract_followup_options`와 프런트 `extractFollowupData` 규칙을 하나로 통일할 것.
15. **추천 주제 중복 판정 강화**: 현재 bigram 중복 판정은 "스쿨넷이 뭐예요?"와 "스쿨넷서비스가 무엇인가요?"를 다른 주제로 본다. FAQ ID 단위로 이미 답했거나 추천한 ID를 제외하고, 본문에 이미 나온 항목(설치 위치, IP·MAC)도 거를 것.
16. 추천 말풍선 20개 중 14개가 되묻기 후보 폴백(FAQ 질문 원문)이다. 문체가 섞이고, 관련도가 낮은 후보(0.25 등)도 노출된다. 폴백에도 최소 점수와 문구 정규화를 적용할 것.
17. 거절 문구가 네트워크와 무관한 질문(앰프, 급식)에도 스쿨넷 지원센터 번호를 안내한다. 범위 밖이면 담당 부서 일반 안내로 바꿀 것.

### P2. 측정 가능성

18. 되묻기 응답(`type=clarify`)에 `timings`·`elapsed_seconds`가 없어 서버 측 지연을 측정할 수 없다. 응답 스키마에 포함할 것.
19. 매칭된 FAQ ID는 `scenario_match.matched_id`나 trace 문자열에서만 얻을 수 있다. 근거는 `document_name`만 있고 문서 slug가 없다. 평가 러너용으로 `faq_id`, `document_id` 필드를 응답에 추가할 것.

## 6. 데이터셋 개선 사항

**공통**

- 입력 스키마를 통일할 것. 예를 들어 되묻기 버튼 입력이 Claude·Codex는 `input.faq_id`, Gemini는 `input.clarify_response.choice`로 다르다. 후보 위치 표기도 dict(Claude)와 list(Codex)로 나뉜다.
- 실제 거절 라우트 값은 `abstain`이다. 가이드 4장 예시와 데이터의 `route_in`에 `abstain`을 넣을 것.
- 근거 `document_id`는 `ragdata/document_metadata.json`의 slug로 맞출 것(Gemini의 `cat_0012` 등은 대조 불가).
- FAQ 원문과 똑같은 입력은 정확 일치 우회로 정규화를 거치지 않으므로 DS-2에 쓰지 말 것.
- 되묻기 필수 후보는 실제 후보 생성 방식(semantic 상위 2개)과 맞지 않는 기대가 많았다(3/8). 본 제작 전에 "필수"와 "허용"을 다시 나눌 것.

**테스트데이터_Claude**

- CL_DS5B_001의 `route_in`을 `["abstain"]`으로 고칠 것.
- CL_DS3B_001의 필수 후보 스쿨넷:46이 실제로 나오지 않았다. 필수 조건을 "로그인 관련 후보 2개 이상"으로 완화하는 것을 검토한다.
- CL_DS4A·DS4B 시드는 겹치는 FAQ 쌍에 걸려 체인 측정이 안 됐다. 과발동 회귀용으로 남기고, 후속 체인 측정용 시드를 따로 추가할 것.

**테스트데이터_Codex**

- P_DS2B_001 입력이 FAQ 학내망:10 원문과 같다. 변형 문장으로 바꿀 것.
- P_DS3A·DS3B가 같은 질문을 쓴다. 입력 방식 비교 목적은 유지하되, 본 제작에서는 다른 질문도 섞을 것.

**테스트데이터_Gemini**

- 세션 수가 16개라 가이드의 그룹당 2~3세션을 넘는다(DS-5 5세션). 파일럿 비교 시 그룹별로 맞출 것.
- PILOT_DS1A_001 `target_faq_ids`에 시나리오 노드가 섞여 있다. PILOT_DS2A_001의 `canonical_question_id: rag_01`은 FAQ ID가 아니다.
- PILOT_DS2B_001 입력에는 정규화할 표현이 없다(ON/OFF 결과가 같음).
- PILOT_DS2C_001은 학내망:10이 정답으로 더 적합하다. 기대값 무선망:13을 재검토할 것.
- PILOT_DS3B·DS3C의 기대 후보는 실제 후보와 겹치지 않았다. FAQ 원문 기준으로 다시 정할 것.
- PILOT_DS5A_002의 기대 "-72dBm 이상"은 원문 "-72dbm >"와 표기가 다르다. 허용 표기에 "초과"를 추가할 것.

## 7. 측정하지 못한 것

- 브라우저 DOM(실제 버튼 렌더링·클릭 후 상태). 후속 버튼은 프런트 파서 로직을 Python으로 옮겨 계산했다.
- 오프라인 HTML은 브라우저로 실행하지 않았다. 내장 시나리오 데이터 29개 노드가 `scenarios.json`과 같다는 것과, 시나리오 3경로의 전이가 맞다는 것만 확인했다.
- SSE `/api/chat/stream` 경로, GCP 운영 서버(8002) 경로, sLLM 2차 마스킹(`PII_BACKEND=sllm`), strict 방화벽 모드.
- 반복 실행 분산. DS-5A만 2회 실행했고 결과가 같았다. 콜드 스타트 지연은 별도로 측정하지 않았다.
